## Что доказывают серверные тесты

- Отдельный пользователь не может читать, изменять или повторно получать чужой диалог.
- Refresh token одноразовый; старый access token после ротации не действует.
- Удаление данных удаляет сессии, диалоги, события и избранное через FK cascades.
- Чтение каталога и карточки не вызывает ИИ. Стартовое «хочу квартиру», готовые фильтры и кнопка объяснения обходятся без модели.
- RAG ограничен двумя вызовами; выдуманные IDs цитат отбрасываются, квота предотвращает дополнительные вызовы.
- Быстрый застройщик отдаёт карточки до timeout медленного. Ошибка источника не обновляет дату наблюдения старой квартиры.
- Старый снимок не может вернуть проданную квартиру; неполный ответ не удаляет другие записи; пустой полный снимок меняет только свой город и только при явном разрешении.
- Идемпотентный повтор не запускает модель повторно. Контекст частично показанных карточек сохраняется и при разрыве соединения.
- Действующая школа **в бигвилле** может учитываться по данным застройщика без OSM. Запланированная/неизвестная школа, в том числе имеющая координаты, не считается действующей. Текст с явным будущим временем не принимается как `operating`.
- Контекст ограничен своим ЖК/бигвиллем и застройщиком; удалённые сведения не восстанавливаются старым документом.
- Redis-счётчики атомарны, чужой token не освобождает lease.
- Основные ответы каталога представлены типизированными схемами в OpenAPI.

## Реальные источники

Публичные методы BI Group повторены без cookies и ключей Chrome. В сквозном запросе Астаны для двухкомнатных квартир до 35 млн ₸ пришло 210 записей двумя порциями; сформирована подборка из 20 и успешно повторно прочитана одна квартира. Это свидетельство конкретного запуска, не постоянное число квартир и не доказательство полного покрытия рынка.

В отдельном HTTP-прогоне локального контейнерного API с тёплым каталогом: первое событие около **15 мс**, первые карточки около **41 мс**, завершение около **0,88 с**. Использовался базовый режим без LLM. Эти числа не являются SLO, статистикой production или нагрузочным тестом.

Поддержаны IDs пяти казахстанских городов из публичного контракта BI Group. Полные live-прогоны каждого города и каждого статуса не утверждаются выполненными.

Со страницы Aisar проверены два небольших фрагмента об инфраструктуре. В БД они хранятся как **два факта с неизвестным состоянием**: школы `nearby`, детские сады `unspecified`. Точные координаты, работа объектов и места для зачисления из этих фрагментов не следуют. Это курированный пример, не автоматический непрерывный сбор всех лендингов.

OSM проверялся как дополнительный импорт. Он не требуется для запуска, не используется как доказательство отсутствия новой инфраструктуры и не опрашивается автоматически на каждом запросе.

## Условия публичного выпуска, которые ещё не выполнены

1. **Настроить реальный ключ и модель ИИ**, выполнить русскоязычные evals и измерить качество/расходы. Платная LLM в этой работе live не вызывалась; schema/budget-ветки проверены тестовым клиентом.
2. **Подключить остальных застройщиков** и каналы инфраструктуры. Готова интеграция BI Group по квартирам, generic feed и импорт контекста. Универсального адаптера всех компаний и автоматического парсера всех их описаний нет.
3. **Развернуть на выбранном сервере**: домен, TLS, отдельные DDL/DML-роли PostgreSQL, trusted proxy, мониторинг и резервные копии. Production-настройки защищены проверками, но публичная среда здесь не создана.
4. **Проверить нагрузку и восстановление**: реальные SLO, ёмкость, backup/restore drill, обновление/откат и отказ инфраструктуры. Такие результаты не подменяются unit-тестами.
5. **Подготовить выпуск iOS**: Apple Developer team, физический iPhone, подпись/TestFlight, актуальные privacy/terms и условия использования материалов поставщиков. App Store Connect не настраивался.

Покрытие нового источника подтверждается отдельно по его договорённому формату и фактическим live-ответам. Свежий ответ API подтверждает наблюдение, но не бронирование и не отсутствие ошибок во внутренней системе застройщика.
