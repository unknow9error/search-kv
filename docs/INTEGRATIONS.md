# Источники данных

## BI Group

Проверено 12 сентября 2026 года. Методы обнаружены в публичном каталоге в Chrome, затем прочитана [OpenAPI-схема](https://apigw.bi.group/sales-picker/v3/api-docs). Запросы успешно повторены с сервера **без пользовательских cookies, токенов, clientId и dealId**.

База: `https://apigw.bi.group/sales-picker/microfe-v3/`.

| Метод | Назначение |
|---|---|
| `POST filter` | Доступные города, типы, диапазоны и состав фильтров |
| `POST realEstateList` | ЖК, координаты, исходная страница и `bigVille` |
| `POST placementList` | Страница квартир с `pageNo`, `pageSize`, `cityUUID`, `propertyTypes`, `priceMax`, `roomCounts` |
| `POST placement` | Конкретное помещение по `placementUUID` |

Это методы чтения, несмотря на HTTP POST. Операции бронирования, покупки и заявок не реализуются адаптером.

Проверены карта городов, персональный запрос Астаны, пагинация и проверка квартиры. Полные live-сценарии остальных городов не утверждаются проверенными. Публичный контракт может измениться; адаптер при неожиданном формате прекращает импорт. Права на регулярную агрегацию и показ материалов BI должны быть согласованы владельцем продукта до публичного распространения.

### Семантика

- Признак свободного помещения — пара UUID статуса и название `Свободно`. Бронирование исключается. `Снятие брони`, `Снятие резерва`, `Расторжение` остаются `unknown`, пока их семантика не подтверждена поставщиком; факт `canBuy=true` не заменяет такой договорённости.
- Берётся `totalPrice`; скидка клуба/акции не выдаётся как доступная каждому пользователю.
- `deadLine` в прошлом не доказывает фактическую сдачу дома.
- Координаты принадлежат ЖК. При отсутствии/аномалии координат возвращается `null`, а не центр города.
- UUID города берётся из метаданных проекта; несоответствующие городу и типу недвижимости записи исключаются.
- Поиск ограничен тремя страницами по 150 записей; клиент получает ограниченную подборку, а не обещание полного перебора рынка. Фоновый скан продолжает страницы с сохранённого курсора и чередует города. Полная синхронизация рынка одним запросом не заявляется.
- Пагинация BI не является согласованным снимком: её завершение не удаляет отсутствующие объекты. Устаревшие записи истекают и перепроверяются по ID.

## Второй и следующие застройщики

Добавьте реализацию `ApartmentProvider` и запись конфигурации. Реальные адаптеры должны иметь контрактные тесты на фактический ответ, статус, валюту, уникальность и пагинацию. Не переименовывайте generic feed в название застройщика без реализации его контракта.

Generic `json_feed` ожидает:

```json
{
  "as_of": "2026-09-12T10:00:00Z",
  "complete": false,
  "allow_empty": false,
  "scope_city": "Астана",
  "next_cursor": null,
  "items": [],
  "project_contexts": []
}
```

Пути `GET /apartments?city=...&limit=500&cursor=...` и `GET /apartments/{external_id}`. Ответ проверки — неполный снимок с ровно одним совпадающим ID. Если доступен только поисковый ответ, он всегда `complete=false`. Для полной пагинации `as_of` стабилен между страницами; при изменении версии импорт отклоняется. Точная модель помещения — `ListingInput` в сервере и OpenAPI приложения.

URL источника и изображения должны быть HTTPS. Адрес API фиксируется администратором в конфигурации; ИИ его не выбирает. Перенаправления не выполняются, тела ответов ограничены, credentials берутся из явно указанной переменной окружения.

## ЖК, бигвилли и инфраструктура

Квартиры передают `complex_id`, `bigville_id`, `bigville_name`. Документ инфраструктуры передаётся отдельно или в `project_contexts` feed:

```json
{
  "provider_id": "partner-id",
  "scope_type": "bigville",
  "scope_id": "upstream-bigville-id",
  "source_url": "https://developer.example/project",
  "observed_at": "2026-09-12T10:00:00Z",
  "expires_at": "2026-10-12T10:00:00Z",
  "facts": [
    {
      "kind": "school",
      "name": "Школа из проекта застройщика",
      "state": "planned",
      "relation": "within",
      "expected_opening": "2028 год — по заявлению застройщика",
      "evidence": "Точная выдержка из документа с указанием будущего строительства."
    }
  ]
}
```

**Пример формата, не реальные сведения о BI.** `relation` отдельно описывает размещение: `within`, `nearby` или `unspecified`. Тема документа о ЖК не означает, что вся описанная инфраструктура находится внутри ЖК. Фильтр «в ЖК/бигвилле» требует `within`. Не импортируется автоматически. `scope_type` — `complex` или `bigville`; `state` — `operating`, `planned`, `under_construction`, `unknown`. Неустановленное состояние должно оставаться `unknown`. Для `operating` нужна соответствующая формулировка источника. Дата открытия не выдумывается. Нельзя превращать маркетинговый план в обещание работающего объекта.

```sh
cd backend
.venv/bin/python -m app.services.project_context /path/to/reviewed-context.json
```

Импорт заменяет факты **одного документа в одном scope**, сохраняет версию и не позволяет старому документу восстановить удалённые сведения. Для автоматического подключения конкретного застройщика нужен его канал структурированного контекста или отдельный парсер опубликованных материалов. В проверенном BI sales-picker описания инфраструктуры не обнаружены. Автоматический универсальный парсер всех лендингов не заявляется готовым.

Если подключать LLM-извлечение из неструктурированных описаний, запускать его фоново **один раз на изменённый хеш документа ЖК/бигвилля**. Проверять буквальную принадлежность цитаты документу и статус будущего времени; не запускать его для каждой квартиры или GET. Текущий импорт принимает уже структурированные/проверенные факты.

## OSM — необязательный дополнительный канал

Однократный импорт возможен после появления координат ЖК в БД:

```sh
cd backend
.venv/bin/python -m app.services.places --city Астана --endpoint https://your-overpass-endpoint.example/api/interpreter
```

Запрос ограничен областью найденных ЖК. Импортируются названные объекты, рассчитываются расстояния до координат ЖК. API поиска не обращается в OSM. Новые записи каталога получают связи из уже импортированной локальной выборки. Планируемые и отсутствующие на карте новые проекты требуют данных застройщика.

[Overpass usage guidance](https://wiki.openstreetmap.org/wiki/Overpass_API#Public_Overpass_API_instances), [ODbL и атрибуция](https://www.openstreetmap.org/copyright). Публичный Overpass не является production-SLA; в коде не включён регулярный опрос публичного endpoint.

В комплекте есть два проверенных фрагмента [страницы Aisar](https://bi.group/ru/landing/aisar) в `backend/data/contexts/bi-group-aisar.json`: упоминание двух школ рядом и детских садов. Они автоматически загружаются при включённом адаптере BI Group. Их состояние оставлено `unknown`: этот фрагмент не подтверждает работу объектов, точные координаты или доступность мест. Срок пересмотра — 30 дней; это ограниченный курированный пример, не автоматический сбор всех лендингов.

У элементов `amenities` в generic feed также должен быть явный `state=operating`, чтобы они участвовали в фильтре действующих объектов. По умолчанию состояние неизвестно.
