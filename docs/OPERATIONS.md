# Эксплуатация

## Production-конфигурация

Production — отдельная среда и отдельная БД. Не переносите демонстрационную SQLite в production. На старте режим `production` отклоняет SQLite, отсутствие Redis, автоматическое создание таблиц, wildcard hosts и отсутствующие публичные privacy/terms URLs.

1. Подготовить сервер, DNS и TLS. Взять `.env.example`, сгенерировать уникальные секреты, задать `MEKEN_ENV=production`, явный домен в `MEKEN_ALLOWED_HOSTS`, ссылки политики/условий, модель и серверный API key. Разрешения файла `.env`: `0600`.
2. Конфигурация поставщиков — проверенные адаптеры и credentials через переменные окружения. BI Group доступен как отдельный адаптер; его публичность не заменяет договорённость о коммерческом использовании материалов.
   Настроить отдельные роли БД: `MEKEN_DATABASE_URL` для API/worker с DML-правами и `MEKEN_MIGRATION_DATABASE_URL` для миграций с DDL-правами. Production API откажется работать под ролью superuser/CREATEDB/CREATEROLE. Локальная роль Docker является администратором только для разработки. Runtime-роли нужны CONNECT, USAGE схемы, SELECT/INSERT/UPDATE/DELETE таблиц и USAGE/SELECT sequences; default privileges новых миграций должны выдаваться от имени владельца объектов.
3. `docker compose up --build -d`. Миграции выполняются отдельным процессом до API. БД и Redis по основному compose не имеют опубликованных портов. API слушает только loopback хоста.
4. Настроить Caddy на хосте по `infra/Caddyfile`, переменная `MEKEN_DOMAIN` — ваш домен. Не включать буферизацию SSE. Проверить конфигурацию `caddy validate` на выбранной версии Caddy перед запуском.
5. Настроить trusted proxy адрес для Uvicorn (`FORWARDED_ALLOW_IPS`), соответствующий адресу прокси с точки зрения контейнера. Нельзя доверять любому `X-Forwarded-For`: иначе IP-лимиты обходятся. Проверить, что разные реальные клиенты различаются в request.client. Не передавать `*` для произвольной сети.
6. Подключить метрики по внутреннему адресу с `Authorization: Bearer <MEKEN_METRICS_TOKEN>`. Публичный Caddy закрывает служебные пути. Логи не включают тексты чатов, токены или тела ответов застройщиков.

Для реального iPhone нужен доступный с телефона HTTPS API, а не `127.0.0.1` компьютера. Release-сборка отклоняет localhost, `.invalid` и не-HTTPS endpoint. Задать `DEVELOPMENT_TEAM`, bundle ID, подпись, App Store Connect и выполнить тест на физическом устройстве. Privacy manifest и тексты должны соответствовать фактически включённым сервисам и опубликованной политике.

## Ресурсы и масштабирование

- Старт: один API-процесс и один worker. Одно приложение обслуживает много асинхронных запросов; число процессов выбирается по измерениям, памяти и лимиту соединений PostgreSQL.
- У каждого процесса собственный SQLAlchemy pool и HTTP pool. При увеличении реплик пересчитать суммарные подключения к БД. Redis сохраняет общие лимиты и блокировки.
- Ограничения модели по умолчанию: 40 calls/user/day и 2000 calls/service/day, до двух calls/turn. Отказ/некорректная схема/timeout переводят в базовый подбор. Автоматических SDK retries нет.
- Жёсткие фильтры выполняются в SQL до LIMIT. Преимущество желательных POI и свежести вычисляется без модели. Причины и компромиссы отражают конкретные свойства, а не вымышленный процент совпадения.
- BI foreground: до 3 × 150 записей с ранними порциями. Worker продолжает ограниченные проходы по курсорам; города чередуются. Это не полное покрытие всех квартир за один цикл. Контролировать возраст каталога и объём импорта до увеличения трафика.
- OSM не является обязательной зависимостью, не вызывается из поиска и не опрашивается автоматически публичным endpoint. Контекст ЖК/бигвиллей — отдельные документы; подключение соответствующего канала каждого застройщика является задачей интеграции.

## Проверки после развёртывания

Внутренние `/health/live` и `/health/ready` должны отвечать успешно. `ready` проверяет БД и Redis. Дополнительно проверить:

- Новый анонимный пользователь получает свою сессию; чужой диалог недоступен.
- «Хочу квартиру» задаёт понятные уточнения.
- Карточки приходят до завершения опроса остальных источников; прокси не удерживает SSE.
- Источник с timeout не останавливает остальные результаты; данные не подменяются demo.
- Перепроверка конкретного помещения обновляет цену/статус и не является бронью.
- Планируемая школа не отображается как действующая; отсутствие данных показано как неизвестность.
- Реальные стоимость, задержки и отказы выбранной модели на русскоязычном eval-наборе.
- Удаление данных отзывает сессии, удаляет диалоги/избранное, затем данные удаляются из ротации резервных копий в соответствии с установленной политикой.

## Резервные копии и восстановление

```sh
mkdir -p backups
docker compose exec -T db pg_dump -U meken -d meken -Fc > backups/meken.dump
```

Каталог `backups` должен быть закрыт от публичного доступа, файлы — зашифрованы до отправки во внешнее хранилище. Автоматизацию расписания, место хранения и срок хранения выбирает владелец сервера. Не хранить dumps в Git.

Проверять восстановление в **отдельную БД**:

```sh
docker compose exec -T db createdb -U meken meken_restore_check
docker compose exec -T db pg_restore -U meken -d meken_restore_check --no-owner < backups/meken.dump
```

Не использовать `--clean` по production БД без согласованного окна и актуальной копии. Для отката кода сохранить предыдущий образ. Откат схемы делать только после оценки потери данных; новая миграция часто безопаснее downgrade. Не удалять Docker volumes при обычном обновлении.

## Метрики и диагностика

Доступны `meken_provider_calls_total`, `meken_provider_seconds`, `meken_ai_calls_total`, `meken_ai_tokens_total`, `meken_turns_total`, `meken_http_seconds`. Для SSE HTTP-гистограмма отражает время до заголовков; окончание turn учитывается отдельно событием/статусом. Dashboard/alert rules не установлены на внешний сервис.

Рекомендуемые сигналы: доля failed/timeout по каждому источнику, отсутствие успешных импортов, рост возраста наблюдений, неуспешные turns, бюджет ИИ, соединения и свободный диск PostgreSQL, Redis errors. Значения порогов нужно калибровать по нагрузочному прогону; недоказанные SLO не заявляются.

## Ограничения безопасности и продукта

Анонимная сессия — удобный старт, но не перенос учётной записи между устройствами. Для публичного дорогого ИИ-трафика оценить App Attest/подтверждённую идентичность и лимиты на злоупотребления. Модель не имеет write/tools для внешних систем, бронирования, оплаты или связи с отделом продаж. Данные пользователей не отправляются застройщикам.

Любой каталог может ошибаться. Даже свежий успешный ответ API не гарантирует актуальность внутренней системы застройщика и не создаёт юридического обязательства предоставить квартиру. Это отражается в карточке и проверке наличия.
