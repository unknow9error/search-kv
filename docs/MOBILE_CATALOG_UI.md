# Нативный интерфейс каталога ЖК

Основной интерфейс iOS и Android заменён 13 страницами из галереи `meken-aggregator-design-20261005`. Фон белый независимо от системной темы. Старые квартирные страницы не входят в новую навигацию. Авторизация, защищённое хранение и восстановление используют существующий слой, а каталог подключён к новым `/v1/projects` API.

Первый запуск содержит вступительную анимацию: фото мягко проявляется с масштабом 1.035 → 1, затем с интервалом 100 мс появляются заголовок, описание, выбор города и кнопка. Полная последовательность занимает 960 мс и не задерживает подключение к API. iOS учитывает Reduce Motion, Android использует системный масштаб длительности анимаций. Перерисовки при загрузке каталога не запускают вступление повторно. Нативные записи: `artifacts/mobile/welcome-20261005`.

Дополнительные дочерние состояния: источники каталога, сообщение о неточности, защищённое восстановление, создание кода, подтверждение удаления. Новые UI исходники: `ios/Meken/Features/Catalog` и `android/app/src/main/java/kz/unknown/meken/ui/catalog`. Контрактные DTO: `ios/MekenCore/Sources/MekenCore/ProjectModels.swift` и `android/core/.../catalog/ProjectModels.kt`.

Поиск и карта сохраняют критерии и сортировку. Отмена фильтров не применяет черновик. Сравнение допускает 2–3 ЖК и горизонтальную прокрутку без уменьшения текста; цена ЖК «от» и минимум лотов остаются разными видами цены. Планировка не получает выдуманных цены, этажа или наличия. Неизвестные поля показываются явно. Самостоятельный базовый проектный разговор сохраняет UUID создания и запроса до отправки в защищённом хранилище и использует их при повторе. История загружается с серверным курсором. Избранное кешируется отдельно по endpoint/пользователю; смена профиля не смешивает данные.

Новые маршруты включаются по capabilities; старый сервер не подменяется демонстрационными результатами. Production URL и release guards сохранены. Выкатка backend и публикация приложения не выполнялись.

Если сервер не сообщает `project_catalog`, выбор города не запрашивает facets, а вкладки и дочерние страницы показывают явное состояние недоступности каталога. Профиль, документы и управление аккаунтом доступны отдельно. Сетевые операции каталога также пропускаются в offline режиме, сохраняя возможность читать кеш. На Android проверены поиск, избранное, профиль, история и источники при отсутствии capability: запросов к отсутствующим API — 0.

Android карта использует локально включённый Leaflet 1.9.4 и обычные HTTPS тайлы OpenStreetMap с видимой атрибуцией и стандартным HTTP кешем. Координаты берутся только из ответа API. Геолокация не запрашивается. WebView не получает Bearer-токены. В JavaScript передаются сериализованные публичные поля; выбор ID ограничен текущими результатами. Источники реализации: [Leaflet](https://leafletjs.com/examples/quick-start/), [политика тайлов OSM](https://operations.osmfoundation.org/policies/tiles/).

Проверки и 26 нативных снимков: `artifacts/mobile/catalog-20261005/verification.json`. iOS: сборка, все 13 страниц в UI-тесте, 19 существующих и 4 новых Core теста. Android: сборка/lint, 17 Core и 31 app тест, переходы через все 13 страниц. Проверка интерфейса использовала отдельный SQLite/demo API, данные и рисунки макетов не импортировались в публичный или production каталог. Отдельные фикстуры выдачи и полной детали проверяют действительное различие их DTO. Проверено восстановление HTTP/1 чтения после закрытия старого соединения; автоматическое повторение операций аккаунта и отправки сообщений исключено.
